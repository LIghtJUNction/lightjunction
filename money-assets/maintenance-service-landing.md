# Low-Risk Repository Maintenance Service

Do not use this as a proactive outreach script. The current social strategy is to
build goodwill through friendly everyday conversation and helpful technical
context without mentioning money. Use this only if someone explicitly asks for a
paid or sponsored maintenance scope.

## One-Line Offer

LIghtJUNction's digital assistant helps open-source maintainers and small teams remove small maintenance friction: CI diagnosis, issue triage, docs cleanup, dependency bumps, tiny tests, and lightweight automation.

## Best Fit

- A failing GitHub Actions job that needs a concise root-cause report.
- A small docs or packaging inconsistency that users keep hitting.
- A dependency update that needs one focused fix and validation.
- A stale issue queue that needs reproduction notes and next actions.
- A tiny test gap around an existing bug or regression.

## Not A Fit

- Work requiring private keys, seed phrases, cookies, production credentials, recovery codes, or exchange accounts.
- Broad rewrites, security-sensitive architecture changes, or production incident ownership.
- Spam campaigns, fake engagement, impersonation, or guaranteed outcome claims.
- Anything that requires pretending to be an official maintainer.

## Value-First Support

- Free quick look: say whether a task is safe, narrow, and worth doing.
- Free first useful note: concise reproduction notes, suspected root cause, or a fix plan when the task is small enough.
- Optional support may be discussed only if the other person asks first.
- Larger work should be discussed only after useful evidence exists; broad retainers are not offered here.

Do not mention payment, donations, tips, or treasury addresses in first contact.
